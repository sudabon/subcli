# policy-guard Specification

## Purpose
各社（Anthropic / OpenAI / Google）の利用規約の範囲内で `subcli` を安全に動作させるため、許可マトリクスによる実行前ガード、AI エージェント配下実行の検出、単一アカウント制約、および CI で強制する静的遵守検証の要件を定義する。

## Requirements

### Requirement: 許可マトリクスによる実行前ポリシー判定
システムは、プロバイダ・認証モード（`subscription` / `api_key`）・操作種別（`login`, `open`, `run`, `resume`, `compare`, `chain`）・実行コンテキスト（TTY の有無および他 AI エージェント配下かどうか）に基づき、これらの操作で公式 CLI の子プロセスを起動する前に操作の可否を判定しなければならない（SHALL）。不許可と判定された場合、システムは子プロセスを一切起動せず、日本語の拒否理由と根拠となる公式ドキュメント URL を表示して非ゼロ終了コードで終了しなければならない（MUST）。

#### Scenario: claude / codex のサブスク認証で許可操作を実行する
- **WHEN** `claude` または `codex` の `subscription` モードで `login`, `open`, `run`, `resume`, `compare`, `chain` のいずれかの可否を判定する
- **THEN** ポリシー判定は許可を返す

#### Scenario: agy サブスク認証でヘッドレス・比較・連携を実行しようとする
- **WHEN** `agy` の `subscription` モードで `run`, `resume`, `compare`, `chain` のいずれかの可否を判定する
- **THEN** ポリシー判定は拒否を返し、日本語の理由と公式参照 URL を提示し、子プロセスを起動しない

#### Scenario: agy API キーモードで全操作を判定する
- **WHEN** `agy` の `api_key` モードで `open`, `run`, `resume`, `compare`, `chain` のいずれかの可否を判定する
- **THEN** ポリシー判定は許可を返す

### Requirement: agy サブスクの対話起動・ログインにおける TTY および非エージェント制約
システムは、`agy` の `subscription` モードにおける `login` および `open` 操作を、標準入力・標準出力がともに TTY であり、かつ他の AI エージェント配下で実行されていない場合にのみ許可しなければならない（SHALL）。

#### Scenario: ターミナルから直接 agy を open する
- **WHEN** ユーザーが標準入力・標準出力がともに TTY であり他の AI エージェント配下ではない環境から `subcli open agy`（`auth=subscription`）を実行する
- **THEN** ポリシー判定は許可を返す

#### Scenario: 他の AI エージェント配下または非 TTY から agy を open / login する
- **WHEN** Claude Code や Codex 等の他 AI エージェントのシェル実行ツール配下、または標準入力・標準出力のいずれかが非 TTY、または祖先プロセスを確認できない環境から `subcli open agy` または `subcli login agy`（`auth=subscription`）を実行する
- **THEN** ポリシー判定は拒否を返し、検出理由と公式参照 URL を表示して終了する

### Requirement: 他 AI エージェント配下実行のヒューリスティック検出
システムは、実行環境が他の AI エージェント配下にあるかを以下の両方で検出し、いずれかに該当した場合はエージェント配下と判定しなければならない（SHALL）。
1. Phase 0 で確定した既知のエージェント環境変数（例: `CLAUDECODE`、`CODEX_SANDBOX*` 等）の存在。
2. 親プロセスチェーンを最大 10 階層まで遡った際に、既知の AI エージェントプロセス名（`claude`, `codex`, `agy`, `opencode`, `openclaw`, `cursor-agent` 等）が存在すること。

#### Scenario: 環境変数によるエージェント配下検出
- **WHEN** 既知の AI エージェント用環境変数が設定された状態で `subcli` を実行する
- **THEN** システムは他 AI エージェント配下と判定し、検出した環境変数名を検出理由として記録する

#### Scenario: 親プロセスチェーンによるエージェント配下検出
- **WHEN** 環境変数が未設定であっても、最大 10 階層以内の祖先プロセスに既知の AI エージェント名が含まれる状態で `subcli` を実行する
- **THEN** システムは他 AI エージェント配下と判定し、検出した祖先プロセス名を検出理由として記録する

### Requirement: 複数アカウント自動切替と外部サーバ化の禁止
システムは、同一プロバイダに対して複数アカウントを切り替える機能、および HTTP サーバ・MCP サーバ等の外部公開機能を提供してはならない（MUST NOT）。

#### Scenario: 複数アカウント設定の拒否
- **WHEN** 同一プロバイダに複数のアカウント設定を含む構成が与えられた場合
- **THEN** システムは設定エラーとして読み込みを拒否する

### Requirement: 静的遵守テストによる継続的検証
本リポジトリのテストスイートは、以下を自動検証する静的遵守テストを含まなければならない（SHALL）。
- 実装コード内に各社公式 CLI の認証ファイルパスやキーチェーンアクセス API が含まれないこと。
- ネットワーク直接呼び出し（`net/http`）の依存が Google AI Studio フォールバック専用領域以外に存在しないこと。
- 各プロバイダが生成する引数に権限確認をバイパスする危険フラグが含まれないこと。
- 許可マトリクスの全セル（プロバイダ × 認証モード × 操作種別 × 実行コンテキスト）が期待どおり判定されること。

#### Scenario: CI での静的遵守テスト実行
- **WHEN** 自動テストスイートを実行する
- **THEN** 認証情報非アクセス検査、HTTP 依存範囲検査、危険フラグ検査、および許可マトリクス全セル検査のすべてが合格する
